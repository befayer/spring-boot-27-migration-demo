# Миграция на Spring Boot 3.5

## Зачем

Spring Boot 2.7 больше не получает исправлений безопасности в OSS-версии. Сервис нужно перевести на актуальную линию 3.5 без изменений для клиентов.

## Объём

- Spring Boot 2.7.18 → 3.5.x, Java 11 → 17 или 21.
- Все зависимости — на версии, совместимые с Boot 3.5.
- Spring Cloud Sleuth → Micrometer Tracing.
- `javax.*` → `jakarta.*`.
- Spring Security 5 → 6: без `WebSecurityConfigurerAdapter`.
- Конфигурация (`application.yml`) — на актуальные имена свойств.

Вне объёма: новые функции, рефакторинг бизнес-логики, изменения схемы данных, кроме необходимых для совместимости.

## Критерии приёмки

1. `./gw build` проходит на Boot 3.5.x без ошибок.
2. `scripts/contract-check.sh` зелёный: все контрактные тесты проходят.
3. `src/contractTest` не изменён: `git diff boot-2.7 -- src/contractTest` пустой.
4. Существующая база, созданная версией 2.7, продолжает работать: миграции Flyway не переписываются, только добавляются.
5. В логах старта нет предупреждений о неизвестных или удалённых свойствах конфигурации.

## Отчёт

В конце перечислите:

- какие изменения сделаны и почему;
- какие контрактные тесты падали по ходу миграции и в чём была причина;
- результаты сборки и контрактных тестов;
- что не удалось проверить локально.
